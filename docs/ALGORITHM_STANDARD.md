# Algorithm contribution standard

## Directory and metadata contract

Place general algorithms at `algorithms/<numbered_category>/<algorithm_slug>/`,
LLM-specific algorithms at `llms/<algorithm_slug>/`, and VLM-specific
algorithms at `vlms/<algorithm_slug>/`. These are separate top-level
collections with independent README indexes.
**Implementation folders are called `<algorithm_slug>_<language>`.**

The root of every algorithm contains:

- `README.md`: purpose, place in AI, math/algorithm, input/output contract,
  complexity, edge cases, examples, how to test, limitations and references.
- `algorithm.json`: stable metadata for future indexers and validation.
- One directory for each declared language; unsupported languages are omitted.

Example metadata:

    {
      "slug": "dot_product",
      "title": "Dot Product",
      "level": "foundation",
      "summary": "Pairwise vector multiplication and sum.",
      "languages": ["c", "python", "rust", "r", "cuda"]
    }

Valid algorithm levels include `foundation`, `classical_ml`,
`neural_networks`, `information_retrieval`, `vector_search`,
`ai_systems`, `large_language_models`, `computer_vision`, and
`vision_language_models`.

Supported directory names: `_c`, `_python`, `_rust`, `_r`, `_cuda`.
A language is **declared only when both source and tests exist**.

The source/test naming convention is `<slug>.c` / `test_<slug>.c`,
`<slug>.py` / `test_<slug>.py`, `<slug>.rs` (with `#[cfg(test)]` tests),
`<slug>.R` / `test_<slug>.R`, and `<slug>.cu` / `test_<slug>.cu`.

## Implementation priorities

1. **Correctness:** deterministic behavior, documented input validation, and
   reference cases that are the same across available languages.
2. **Small and reusable:** no unnecessary frameworks, application entry
   points or network calls in implementations.
3. **Explainability:** document enough to independently verify the math.
4. **Efficiency:** optimize only with evidence; list time/space complexity.
5. **GPU honesty:** CUDA is an optional implementation using CUDA C++; kernel
   launch costs, device transfers and minimum compute capability matter.

Float behavior may differ across hardware; use declared numerical tolerances
rather than bit-exact comparison when appropriate.

## Required edge cases

For numeric algorithms, consider empty vectors, mismatched lengths, zeros,
negative values, non-finite values, overflow, and known numeric stability
limits. If a case is out of scope, **say so in the README**. For randomized
algorithms, pin seeds and document their source. For approximate retrieval,
measure recall on labeled examples, not just runtime.

## References: APA 7th edition

Every algorithm README must use **APA 7** in its `## References` section:
author or organization, year (or `n.d.`), italicized work title, publisher
when applicable, and a DOI or stable URL when available. Alphabetize the
reference list, use proper authors and verified bibliographic details,
and include author–date citations in the explanatory text when appropriate.
Avoid bare URL lists and fabricated bibliographic metadata.

Book example:

    Strang, G. (2016). *Introduction to linear algebra* (5th ed.).
    Wellesley-Cambridge Press.

Website/documentation example (replace with the actual page details):

    Organization. (n.d.). *Title of documentation page*. https://example.org/page

Use retrieval dates only when APA 7 requires them for changing, unarchived
content. Specify documentation version/commit when applicable. A citation
does not override copyright or software licensing requirements.

## Review and releases

An algorithm PR should not imply all planned languages or GPU variants exist.
Pin benchmarks and input sets before comparing performance. No autogenerated
claim of 100% correctness or production fitness is warranted by passing tests.
